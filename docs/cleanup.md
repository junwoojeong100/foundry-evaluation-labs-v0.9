# 실습 결과 보관과 리소스 보존·정리

[전체 경로](../README.ko.md) · [입문 완료 체크리스트](intro-lab.md#finish) · [공통 환경 준비](setup.md)

**이번 실습의 기본은 생성한 리소스를 모두 보존하는 것입니다.** 선택한 가이드의 마무리에서 이 문서로 이어집니다. 중도 종료한 경우에도 아래에서 본인 상황에 맞는 범위만 확인합니다.

> [!WARNING]
> **리소스 보존 요청이 있는 동안 삭제하지 않습니다.** 터미널을 닫거나 로컬 `results/`를 지워도 Azure 리소스는 삭제되지 않습니다. 중도 종료할 때도 보존 상태와 비용을 확인합니다.

| 내 상황 | 수행할 범위 |
|---|---|
| 실습 완료·중단 후 기본 마무리 | [1. 결과 보관](#save-results) → [2. 보존·비용 확인](#retain-resources)까지만 |
| 환경 소유자가 나중에 삭제를 별도 결정 | 결과 보관 후 [선택 절차 3–5](#delete-resources). 공유 자원 일괄 삭제 금지 |

<a id="save-results"></a>
## 1. 먼저 결과 보관

**할 일:** Azure 리소스를 보존하더라도 학습 결과를 PC에도 남깁니다.

**본인이 실행한 경로의 결과 폴더 전체**를 보관합니다. `report.md`·점수만이 아니라 입력/응답 스냅샷, `foundry-job.json`의 원격 ID, 원본 평가 결과와 검토 기록도 재개·대조에 필요합니다. Foundry의 원본 평가 기록이 더 필요하면 포털에서 먼저 내려받습니다.

| 실행한 경로 | 보관할 로컬 범위 |
|---|---|
| 입문 LIVE/DEMO | 본인의 smoke·baseline·candidate·holdout·추가 사례 결과. LIVE와 `demo-*` 폴더를 구분 |
| 최소 RAG | `results/rag-setup.json`, 조회 결과와 `results/rag-search/`·`results/rag-iq/` 등 해당 실험 파일 |
| 완결형 RAG | `results/advanced/` 전체: 검색·교정·단계별 생성/평가·동결·새 질문 등록·acceptance. [단계별 파일](complete-lab.md#resume) 확인 |

진행 중인 원격 평가는 **`--like` 등 옵션을 유지한 원래 명령 전체**로 조회합니다. 완결형 교정이면 원래 `calibrate`를 사용합니다. 취소가 따로 필요하고 실행 화면이 이를 지원할 때만 본인 작업을 취소하고 상태를 확인합니다. **로컬 터미널 종료가 원격 작업 취소는 아닙니다.**

**완료 확인:** 필요한 로컬 결과와 원격 작업의 실제 상태가 남아 있습니다. 아직 대기 중이면 완료라고 표시하지 않고 다음 조회 시점을 기록합니다. 실제 고객 데이터로 확장했다면 조직의 보존·삭제 정책을 먼저 따릅니다.

<a id="retain-resources"></a>
## 2. 기본: 리소스 보존과 비용 확인

**이번 경로에서는 여기까지만 수행하고 3–5단계는 건너뜁니다.**

1. 준비 때 확인한 계정·구독·전용 그룹을 포털과 대조합니다. 실제로 만든 Foundry 리소스·프로젝트가 남아 있고 지역이 `swedencentral`인지 확인합니다.
2. Foundry의 **Build → Models**에서 생성한 배포가 남아 있는지 확인합니다. 원격 평가를 제출했다면 실행 ID와 상태도 보관합니다. 그룹이 존재한다는 사실만으로 모든 하위 자원이 보존됐다고 판단하지 않습니다.
3. 리소스 그룹·Foundry 리소스·프로젝트·모델 배포·평가 기록과 필요한 역할 할당을 그대로 둡니다. **RAG를 실행했다면 Search 서비스·인덱스·Knowledge Source/Knowledge Base, 완결형의 임베딩·계획 모델 배포도 확인**합니다. `azd down`, 그룹 삭제, 개별 모델 삭제 같은 정리 작업을 실행하지 않습니다.
4. **Cost Management → Cost analysis**를 해당 그룹으로 좁혀 확인합니다. 다른 그룹의 Search·모델을 재사용했다면 그 비용 범위도 소유자와 확인합니다. 비용 집계가 늦을 수 있고, 리소스 보존은 과금 중지가 아닙니다. 예산 알림도 자동 지출 차단이 아닙니다.

**RAG 비용 주의:** [Basic Search는 프로비전 용량 기준으로 유지 비용이 발생](https://learn.microsoft.com/azure/search/search-sku-tier)합니다. semantic/knowledge retrieval의 Free 할당량이 Basic 서비스 자체를 무료로 만들지는 않습니다. 임베딩·LLM 계획·답변·Judge의 사용량도 별도이며, 로컬 생성 토큰 합계만으로 전체 비용을 계산하지 않습니다. 이 확인은 자원을 추가하라는 뜻이 아니라 **실제로 사용한 자원만** 대조하라는 뜻입니다.

**확인할 내용:** **미삭제**, 보존 이유, 다음 확인 시점 또는 조건, 확인한 비용 또는 아직 집계 중이라는 사실. 삭제일을 정하지 않았다면 **“별도 요청 전까지 유지”**합니다. 만들지 않은 자원·미실행 평가는 완료로 표시하지 않습니다.

**보존 완료 확인:** 실제 생성한 자원과 로컬 결과가 남아 있고 보존 조건·비용 확인 상태를 설명할 수 있습니다. 삭제는 실습 완료의 필수 조건이 아닙니다.

## 3. 선택: 삭제할 범위 확인

**나중에 환경 소유자가 삭제하기로 별도로 결정한 경우에만 3–5단계를 수행합니다.**

<details>
<summary>삭제 결정이 있을 때만: 범위 확인부터 삭제 완료까지</summary>

**Azure 포털:** [환경 준비](setup.md#create-project)에서 기록한 **구독 → 리소스 그룹**을 엽니다.

다음 세 가지가 모두 맞을 때만 4단계로 진행합니다.

- 이름과 구독 ID가 준비 때 만든 **본인 전용 그룹**과 같습니다.
- 안의 Foundry 리소스·프로젝트·모델 배포와, 있다면 Search 서비스도 이번 실습의 삭제 승인 대상입니다.
- 다른 사람의 리소스, 다른 실습, 업무용 연결 대상이 섞여 있지 않습니다.

**하나라도 확신할 수 없으면 그룹을 삭제하지 않습니다.** 기존/공유 환경을 썼다면 소유자가 정한 범위의 본인 평가 실행·배포만 개별 정리하고, 공유 프로젝트·모델·리소스 그룹은 유지합니다.

공유 Search의 객체 이름에 본인 접미사가 있어도 서비스 전체의 삭제 권한이나 승인을 뜻하지 않습니다. 다른 그룹에 있는 연결 자원은 이 그룹의 삭제로 함께 정리됐다고 표시하지 않습니다.

## 4. 본인 전용 리소스 그룹 삭제

**할 일:** 더 사용할 계획이 없는 전용 그룹을 본인이 포털에서 삭제합니다.

1. 확인한 그룹의 **Overview → Delete resource group / 리소스 그룹 삭제**를 선택합니다.
2. 삭제될 리소스 목록을 다시 읽습니다. 상위 Foundry 리소스를 지우면 그 프로젝트와 모델도 영향을 받습니다.
3. 확인란에 **이번 실습의 전용 그룹 이름을 직접 입력**하고 삭제를 승인합니다.
4. 알림의 “삭제 요청됨”이 아니라 **삭제 완료**까지 기다립니다.

**리소스 그룹 삭제는 되돌릴 수 없는 작업으로 취급합니다.** 일부 서비스의 soft delete가 전체 프로젝트·평가 결과를 복구해 준다고 가정하지 않습니다.

삭제가 잠금이나 조직 정책 때문에 막히면 **미완료**로 기록합니다. 다른 사람이 만든 잠금이나 조직 정책을 무단으로 제거하지 말고, 해당 통제의 소유자와 정리 방법을 확인합니다.

## 5. 삭제 완료와 비용 확인

포털을 새로 고침해 같은 구독에서 해당 그룹이 사라졌는지 확인합니다. 터미널에서도 읽기 전용 조회로 확인할 수 있습니다.

```bash
az group exists --name "YOUR-LAB-RESOURCE-GROUP" --subscription "YOUR-SUBSCRIPTION-ID"
```

**완료 확인:** 올바른 구독·그룹을 조회한 결과가 `false`이고, 포털에서도 삭제 완료가 확인됩니다. 인증 오류나 403, 단순히 화면에서 안 보이는 상태를 삭제 완료로 기록하지 않습니다.

Cost Management에서 **삭제 전 발생한 비용**도 확인합니다. 비용 반영이 늦을 수 있으므로 즉시 0원으로 보인다고 무료였다고 결론 내리지 않습니다. 삭제는 이미 발생한 비용을 취소하지 않습니다.

구독 자체나 `Microsoft.CognitiveServices` 공급자 등록을 해제하지 않습니다. 삭제된 Foundry 이름이 바로 재사용되지 않으면 새 고유 이름을 사용하고, 이름을 빨리 재사용하려고 자동 purge하지 않습니다.

**확인할 내용:** 삭제한 그룹 이름, 삭제 완료 여부/시각, 확인한 비용 또는 아직 집계 중이라는 사실. 삭제를 하지 않기로 했다면 [보존 절차](#retain-resources)를 따릅니다.

</details>
